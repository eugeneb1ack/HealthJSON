# Установка Health JSON и первый экспорт

Health JSON — приложение для **физического iPhone**. Оно читает только те данные Apple Health, к которым владелец выдал доступ, и создаёт личный экспорт в JSON и CSV. По желанию тот же JSON можно доставлять в приватный HTTPS-приёмник через Tailscale.

## Что понадобится

| Обязательно | Когда нужно |
| --- | --- |
| iPhone с поддерживаемой проектом iOS | Всегда. В проекте задан `IPHONEOS_DEPLOYMENT_TARGET = 26.0`. |
| Apple ID и команда подписи в Xcode | Чтобы установить собранное приложение на свой iPhone. |
| Mac с Xcode и кабелем/беспроводной отладкой | Чтобы собрать этот репозиторий. |
| Данные в приложении «Здоровье» | Иначе экспорт может быть корректным, но пустым. |
| iCloud Drive и личная папка | Рекомендуемый способ хранить и читать файлы с других устройств. |
| Tailscale на iPhone и устройстве-приёмнике | Только для немедленной приватной доставки по API. Не требуется для JSON/CSV в iCloud. |

Simulator не подходит для проверки реального HealthKit-экспорта и фоновой доставки. Для первой крупной выгрузки желательно оставить iPhone разблокированным, подключённым к питанию или с достаточным зарядом, и не закрывать приложение до окончания операции.

## 1. Соберите и установите приложение

1. Клонируйте репозиторий и откройте [`HealthJSON.xcodeproj`](../HealthJSON.xcodeproj) в Xcode.
2. В списке целей выберите **HealthJSON** → **Signing & Capabilities**.
3. Укажите **свою** команду разработчика. Если Xcode сообщает, что идентификатор `com.johndoe.HealthJSON` занят, замените `PRODUCT_BUNDLE_IDENTIFIER` на собственный уникальный идентификатор, например `com.example.HealthJSON`.
4. Убедитесь, что в цели включены `HealthKit` и `HealthKit Background Delivery`. Для этого проекта iCloud app-container не нужен: приложение выбирает папку через системный Files picker и сохраняет доступ к ней в security-scoped bookmark.
5. Выберите подключённый iPhone как destination, затем нажмите Run. При необходимости подтвердите доверие к разработчику на iPhone.

В проекте уже есть режим фона `fetch` и идентификатор задачи `com.johndoe.HealthJSON.refresh`. Если вы меняете bundle identifier, проверьте, что это значение согласовано с настройками проекта и разрешёнными идентификаторами фоновых задач.

## 2. Выдайте доступ к Apple Health

1. Откройте Health JSON на iPhone.
2. В разделе **Синхронизация** нажмите **«Разрешить доступ к Здоровью»**.
3. В системном окне выберите те категории, которые хотите экспортировать. Приложение запрашивает доступ только на чтение и ничего не записывает обратно в Apple Health.

Важно: HealthKit намеренно не сообщает приложению, какие разрешения на чтение были отклонены. Поэтому отсутствие пульса, сна или другого показателя в экспорте не доказывает, что таких данных нет — сначала проверьте доступ в «Здоровье» и наличие самих записей.

## 3. Выберите папку iCloud Drive

1. В разделе **Экспорт** нажмите **«Выбрать папку iCloud Drive»**.
2. В системном браузере «Файлы» выберите личную папку в iCloud Drive и подтвердите доступ.
3. Health JSON создаст внутри неё каталог `Health JSON`. Если выбранная папка уже называется `Health JSON`, она станет корнем без вложенной папки-дубликата.

После успешного экспорта структура будет такой:

```text
<выбранная папка>/Health JSON/
├── Agent/
│   ├── health-context.json   # полный снимок для интеграций
│   ├── health-context.csv    # плоский вариант для таблиц
│   └── Inbox/                # короткие служебные дельты
└── Exports/                  # детальный технический архив HealthKit
```

Если выбранная папка недоступна (например, iCloud Drive временно выключен), приложение не будет терять уже собранные данные: оно использует локальный каталог приложения и показывает это в статусе. Для доступа с другого устройства вернитесь к выбору папки и снова укажите iCloud Drive.

## 4. Создайте первый снимок

Нажмите **«Обновить данные»** на главном экране. Приложение собирает полный снимок за последние 365 дней и сохраняет JSON с CSV атомарно.

Первый экспорт может идти заметно дольше последующих: HealthKit возвращает историю и разные типы данных с разной скоростью. Это не признак зависания, пока на экране меняется состояние экспорта. Архитектура не запускает неограниченное число запросов: одновременно работает до восьми тяжёлых запросов HealthKit, а отдельный неответивший запрос останавливается через 30 секунд и не блокирует весь снимок.

После первого снимка доступны три пути:

- Откройте `health-context.csv` в таблице.
- Передайте свежий JSON или CSV через **«Поделиться»**. Перед открытием системного меню приложение специально создаёт новый полный снимок, чтобы не предложить старый файл.
- Откройте **«Данные здоровья»**, чтобы посмотреть именно сохранённый канонический JSON по дням, неделям, месяцам и году. Кнопка **«Обновить из Здоровья»** там же вручную перезаписывает JSON и CSV и затем обновляет просмотр.

## 5. Выберите формат

В сегменте **«Формат для «Поделиться»»** выберите:

- **JSON** — для своего кода, базы, API и AI-агента. В нём сохранены типы, вложенные объекты и описание порядка компактных строк.
- **CSV** — для Numbers, Excel, LibreOffice, pandas и ручной проверки. Кодировка — UTF-8; составные записи лежат в `details_json`.

Автоматическая синхронизация и Tailscale API используют только JSON: CSV не является безопасной заменой интеграционному контракту.

## 6. При необходимости настройте Tailscale

Вкладка **«Tailscale и API»** нужна только для прямой отправки на ваш частный сервер или другое устройство. Введите не «адрес Mac», а адрес конкретного **приёмника**, например:

```text
https://health-receiver.example-tailnet.ts.net
```

Приложение удалит чужой путь и приведёт адрес к:

```text
https://health-receiver.example-tailnet.ts.net/health-json/v1/import
```

Подходят Mac, Linux, NAS, Raspberry Pi, домашний сервер и любое другое устройство, которое состоит в вашем tailnet и обслуживает этот HTTPS-контракт. Адрес принадлежит пользователю, хранится только на его iPhone и может быть удалён или заменён. Пошаговая настройка — в [руководстве по Tailscale](TAILSCALE_RU.md).

## Автоматическое обновление: чего ожидать

Переключатель **«Автоматическая синхронизация»** подключает наблюдение за изменениями HealthKit. Приложение объединяет близкие изменения максимум на пять минут, а суточный полный снимок забирает поздние правки источников.

Это экономная событийная схема, но не cron: iOS самостоятельно решает, когда дать приложению фоновое время. Если файл критично нужен прямо сейчас, используйте ручную кнопку обновления. Повторные ручные касания не создадут параллельные ресурсоёмкие экспорты — следующий запрос ждёт текущий.

## Быстрая проверка с Mac

Если выбрана корневая папка iCloud Drive, на Mac путь обычно выглядит так:

```sh
SNAPSHOT="$HOME/Library/Mobile Documents/com~apple~CloudDocs/Health JSON/Agent/health-context.json"
python3 mac/healthjson.py validate-agent "$SNAPSHOT"
python3 mac/healthjson.py context "$SNAPSHOT" --days 30
```

Если пользователь выбрал другую папку, путь будет внутри неё. Не ищите «последний JSON» по маске: другое приложение должно читать точный `Agent/health-context.json` и реагировать только на изменение `generatedAt`.

## Типичные проблемы

| Симптом | Что проверить |
| --- | --- |
| Нет части показателей | Разрешения на чтение в «Здоровье», реальное наличие данных и доступный пользователю период истории. |
| В iCloud нет файлов | iCloud Drive включён, папка выбрана повторно, приложение имеет доступ к ней, завершён хотя бы один ручной снимок. |
| Первый экспорт долго идёт | Оставить приложение открытым; у истории много типов и записей. Экспорт сам ограничивает конкуренцию и пропускает недоступный тип вместо вечного ожидания. |
| Просмотр показывает прежние данные | Нажать «Обновить из Здоровья» в самом просмотре и дождаться завершения. Экран обновляется только после атомарной замены снимка. |
| Tailscale-приёмник не подключается | iPhone и получатель подключены к одному разрешённому tailnet, адрес заканчивается на `.ts.net`, `GET /health-json/health` возвращает 2xx, а Tailscale Funnel не используется. |
