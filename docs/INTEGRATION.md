# Контракт интеграции Health JSON

Этот документ отвечает на один вопрос: **как другое приложение получает данные Health JSON?**

Есть два надёжных варианта. Выберите один или поддержите оба:

| Способ | Когда выбирать | Что получает приложение |
| --- | --- | --- |
| **Приватный HTTPS API через Tailscale** | Нужна доставка сразу после экспорта, устройство-приёмник доступно в tailnet. | `POST` с JSON-снимком или короткой дельтой. |
| **Чтение iCloud Drive** | Подходит периодическое чтение, не нужен постоянно доступный сервер. | Точный полный JSON-файл и соседний CSV. |

CSV — интерфейс для таблиц, не замена API. Для базы, мобильного/десктопного приложения, сервера и агента используйте JSON.

Сценарий установки Tailscale и разница между Serve/Funnel находятся в [TAILSCALE_RU.md](TAILSCALE_RU.md). Ниже — протокол, который реализует приложение-получатель.

## 1. Общая модель данных

Полный снимок имеет следующие инварианты:

```json
{
  "schemaVersion": 1,
  "kind": "health-agent-context",
  "generatedAt": "2026-08-29T12:00:00.000Z",
  "period": {
    "start": "2025-08-29",
    "end": "2026-08-29",
    "days": 365,
    "timeZone": "Europe/Moscow"
  },
  "rowFormats": {
    "cumulativeMetric": ["date", "sum"],
    "discreteMetric": ["date", "average", "minimum", "maximum", "latest"],
    "categoryDay": ["date", ["value", "count", "minutes"]],
    "sleepInterval": ["start", "end", "value"]
  },
  "metrics": {},
  "categories": {},
  "activityRings": [],
  "workouts": [],
  "special": {},
  "sleepIntervals": []
}
```

`rowFormats` — часть контракта. В компактных строках поля не повторяются ради размера, поэтому приёмник обязан читать порядок значений из этого объекта, а не полагаться на собственные догадки.

| Поле | Значение |
| --- | --- |
| `schemaVersion` | Версия схемы. Текущая — `1`; неизвестную версию следует отклонить с `422`. |
| `kind` | `health-agent-context` для полного снимка или `health-agent-delta` для недавнего окна изменений. |
| `generatedAt` | ISO 8601 UTC, ревизия конкретного результата экспорта. Для полного файла это главный ключ свежести. |
| `period` | Объявленный диапазон данных и часовой пояс пользователя. Не выводите период только из текущей даты сервера. |
| `updateSemantics` | Инструкция, как применять файл: полный снимок заменяет состояние атомарно; дельта заменяет строки только внутри её окна. |
| `metrics`, `categories`, `activityRings`, `workouts`, `sleepIntervals`, `special` | Нормализованная медицинская информация, доступная в HealthKit при выданном пользователем доступе. Поля могут отсутствовать или быть пустыми. |

Отсутствующий показатель означает «он не был экспортирован», а не «показатель равен нулю» и не «у пользователя точно нет этих данных».

## 2. Приватный HTTPS API через Tailscale

### Адрес

Пользователь вводит **свой** адрес приёмника в приложении, например:

```text
https://receiver.example-tailnet.ts.net
```

Health JSON хранит этот адрес только на соответствующем iPhone и приводит его к единственному импортному URL:

```text
https://receiver.example-tailnet.ts.net/health-json/v1/import
```

Путь, query-параметры и fragment во введённой строке намеренно игнорируются. Поддерживается только `https` и hostname, оканчивающийся на `.ts.net`; IP-адреса и публичные домены не пройдут валидацию. Адрес можно заменить или удалить; он не «привязан к Mac» и не вшит в сборку.

### Проверка доступности

До доставки приложение делает:

```http
GET /health-json/health HTTP/1.1
Accept: application/json
```

Любой `2xx` означает, что сервис готов принять обновление. Рекомендуемый ответ:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"status":"ok"}
```

`401`/`403` показываются как запрет доступа, `5xx` — как временная проблема сервера, а отсутствие ответа за 10 секунд — как недоступность сети или узла.

### Импорт

```http
POST /health-json/v1/import HTTP/1.1
Content-Type: application/json
Accept: application/json
X-HealthJSON-Request-ID: 8d5c118d-dfaf-4e11-8ac1-cc0e8c3eecea

<UTF-8 JSON body>
```

Правила клиента:

- размер одного тела — не более **8 MiB**;
- `X-HealthJSON-Request-ID` — UUID конкретной HTTP-попытки, полезный для трассировки, но не постоянный ключ пакета: при повторе клиент создаёт новый UUID;
- автоматическая и прямая доставка используют JSON, не CSV;
- пакет сначала попадает в защищённую локальную очередь iPhone, а затем отправляется;
- успешным считаются `2xx` и `409`; другие ответы могут быть повторены или обработаны как ошибка согласно таблице ниже.

### Виды пакетов

| `kind` | Что означает | Как применять |
| --- | --- | --- |
| `health-agent-context` | Полный снимок последних 365 дней. `updateSemantics.mode = atomicFullSnapshot`. | Провалидировать целиком и атомарно заменить сохранённый снимок только если `generatedAt` новее. |
| `health-agent-delta` | Короткий снимок последних трёх дней. `updateSemantics.mode = replaceWindow`. | Заменить нормализованные строки только внутри `period`; не дописывать записи без удаления устаревших. |

Сначала всегда приходит или может быть запрошен полный снимок; дельта не является самодостаточной полной историей. После перезапуска приёмника/БД разумно ждать следующий полный снимок или попросить владельца сделать ручное обновление.

### Статусы ответа и повторная доставка

| Ответ получателя | Как его понимает iPhone | Что должен означать на сервере |
| --- | --- | --- |
| `200–299` | Успех; пакет удаляется из очереди. | Обновление сохранено или намеренно безопасно проигнорировано как более старое. |
| `409 Conflict` | Тоже успех; пакет удаляется. | Уже обработанная ревизия/хеш полезной нагрузки или иной ожидаемый идемпотентный дубль. |
| `422 Unprocessable Content` | Этот пакет удаляется без повтора. | JSON невалиден, схема/обязательные поля не поддерживаются. Используйте только для постоянной ошибки контракта. |
| `401` или `403` | Пакет остаётся в очереди; показывается запрет доступа. | Tailnet ACL/grant или ваша прикладная авторизация не допускает отправителя. |
| `500–599` либо сеть недоступна | Пакет остаётся в очереди и повторяется с задержкой от 5 секунд до 5 минут. | Временная неисправность, перегрузка, БД недоступна. |
| Любой другой `4xx` | Рассматривается как временное отклонение и будет повторяться. | Не используйте для окончательной ошибки формата; верните `422`. |

## 3. Как реализовать приёмник правильно

Псевдокод независимо от языка:

```text
on POST /health-json/v1/import(request):
    require content type application/json
    reject with 413 before reading more than 8 MiB
    parse UTF-8 JSON; otherwise return 422
    require schemaVersion == 1
    require kind in {health-agent-context, health-agent-delta}
    require valid ISO-8601 generatedAt and valid period
    require declared rowFormats match supported compact layouts

    begin transaction
      if payload revision/digest is already committed:
          commit; return 409
      if kind is full snapshot and generatedAt is newer:
          replace the entire stored snapshot atomically
      if kind is delta:
          replace normalized rows inside the declared period atomically
      record payload revision/digest for idempotency;
      log request ID only as an audit correlation value
    commit
    return 204
```

Практические детали:

- Храните исходный JSON отдельным атомарным файлом или в транзакции БД, затем строите производные таблицы/агрегации. Не меняйте текущий снимок по частям.
- Сравнивайте даты как ISO 8601 timestamps, а не как строки локального времени, если ваша БД этого не гарантирует.
- Для `dailySum` используйте `[date, sum]`; для дискретного показателя — `[date, average, minimum, maximum, latest]`. Не умножайте и не округляйте значения без учёта `unit`.
- Отдельно обрабатывайте `NSNull`/`null`: это «значение в этот момент отсутствует», а не ноль.
- Не логируйте тело HTTP-запроса, полные health-показатели, UUID или URL с лишними параметрами. Для аудита хватает request ID, времени, статуса, версии схемы и результата валидации.
- Tailscale Serve должен проксировать к сервису на `127.0.0.1`, а правила tailnet должны разрешать только нужный источник. Подробная настройка: [TAILSCALE_RU.md](TAILSCALE_RU.md).

## 4. Чтение из iCloud Drive

Выбранная пользователем папка содержит каталог `Health JSON`. Если пользователь выбрал сам каталог `Health JSON`, он считается корнем без второго вложенного одноимённого каталога.

```text
<выбранная папка>/Health JSON/Agent/health-context.json
<выбранная папка>/Health JSON/Agent/health-context.csv
```

Когда выбрана корневая iCloud Drive, на Mac путь обычно выглядит так:

```text
~/Library/Mobile Documents/com~apple~CloudDocs/Health JSON/Agent/health-context.json
```

Алгоритм читателя:

1. Открывайте только точный путь `Agent/health-context.json`, не выбирайте «самый новый JSON» по маске.
2. Декодируйте файл целиком и проверьте `schemaVersion`, `kind` и `generatedAt`.
3. Если `generatedAt` равно сохранённой ревизии — завершайтесь без обработки.
4. Если ревизия новая — примените полный снимок атомарно и сохраните `generatedAt` как последнюю успешную ревизию.
5. Не используйте `Agent/Inbox` как замену полного файла: это короткие дельты для резервной доставки/диагностики.
6. Не подхватывайте временные файлы или конфликты iCloud как новые данные.

Health JSON записывает CSV первым, затем JSON; каждый публичный файл заменяется атомарно. Если CSV не удалось записать, действующий JSON не сдвигается вперёд. Такая последовательность означает: JSON — единственный авторитетный сигнал о новой полной ревизии.

В проекте есть беззависимостный помощник для корректной обработки начального состояния и следующих изменений:

```sh
python3 mac/healthjson.py agent-delta \
  "$HOME/Library/Mobile Documents/com~apple~CloudDocs/Health JSON/Agent/health-context.json" \
  --state "$HOME/.healthjson-agent/state.json" --days 365
```

Он возвращает `initial`, `changed` или `unchanged`. Для собственного приложения принцип тот же: сохраняйте небольшое локальное состояние ревизии и не пересылайте полный год данных дальше без необходимости.

## 5. CSV

`Agent/health-context.csv` — это UTF-8 CSV с CRLF и RFC 4180 escaping. Заголовки фиксированы:

```text
schema_version, generated_at, period_start, period_end,
record_type, key, type_identifier, unit, aggregation,
date, value, average, minimum, maximum, latest,
count, minutes, start, end, activity, details_json
```

`record_type` принимает `profile`, `metric`, `category`, `sleep_interval`, `activity_ring`, `workout` или `special`.

- Для накопительного `metric` сумма записана в `value`.
- Для дискретного `metric` используются `average`, `minimum`, `maximum`, `latest`.
- Для `category` используются `value`, `count`, `minutes`.
- У колец активности, тренировок и специальных записей исходные сложные данные лежат в `details_json`.

CSV подходит для аналитики в таблице и импорта в BI, но он не заменяет JSON при разработке: отсутствующие/вложенные значения и детали схемы безопаснее обрабатывать из canonical JSON.

## 6. Конфиденциальность и медицинские границы

Данные в этих каналах могут быть чувствительными. По умолчанию ограничьте доступ одному владельцу или конкретному сервису, храните минимум данных, задайте срок хранения и предусмотрите удаление. Не добавляйте медицинские тела в аналитические логи, error tracking или внешние AI-провайдеры без явного согласия владельца.

Интеграция может строить графики, тренды и персональные сводки, но не должна изображать медицинскую диагностику. При потенциально опасных симптомах или значениях приложение/агент должен советовать обратиться к квалифицированному врачу или экстренной службе, а не делать окончательные выводы.
