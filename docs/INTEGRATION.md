# Интеграция Health JSON

Health JSON поддерживает два способа получения данных. Первый — основной приватный HTTPS API в Tailscale; второй — чтение полного файла из iCloud Drive. JSON является контрактом интеграции. CSV — экспорт для людей и табличных программ.

## 1. Прямой API через Tailscale

Это не публичный webhook и не общий диск. Адрес не зашит в приложение: каждый пользователь вводит свой URL приёмника в **Tailscale и API** на собственном iPhone. В новой установке он пустой. Типичный адрес имеет вид:

```text
https://<mac-host>.ts.net/health-json/v1/import
```

Приёмник должен быть опубликован только через Tailscale Serve или другой эквивалентный tailnet-only механизм. Не открывайте этот маршрут в публичный интернет и не добавляйте отдельный токен в iPhone-клиент: аутентификация сети должна проверяться на стороне Tailscale и приёмника.

### Как получить адрес и включить приёмник

1. На Mac поднимите локальный HTTP-приёмник, слушающий только `127.0.0.1:8080`. Он обязан отвечать на `GET /health-json/health` и принимать `POST /health-json/v1/import`.
2. Опубликуйте именно локальный порт внутри tailnet:

   ```sh
   tailscale serve --https=443 http://127.0.0.1:8080
   tailscale serve status
   ```

   Команда покажет URL вида `https://<mac-host>.<tailnet>.ts.net/`. Не используйте `tailscale funnel`: он публикует маршрут в интернет.
3. На iPhone откройте **Tailscale и API** и вставьте URL, который показал Serve: можно корень `https://<mac-host>.<tailnet>.ts.net` или полный URL. Приложение само приводит путь к `https://<mac-host>.<tailnet>.ts.net/health-json/v1/import`, удаляет query-параметры и принимает только HTTPS-адрес с окончанием `.ts.net`.
4. Нажмите «Сохранить адрес», убедитесь в успешной проверке соединения и только затем включите «Отправлять через Tailscale». Адрес можно заменить или удалить в любое время; он хранится только в настройках данного iPhone. Неотправленные обновления привязаны к хешу конкретного адреса, поэтому смена адреса не отправит старые медицинские данные новому получателю.

Tailscale Serve завершает HTTPS на устройстве и применяет правила доступа tailnet. Получатель всё равно должен проверять схему JSON и не доверять телу запроса без валидации. Актуальный синтаксис Serve приведён в [официальной документации Tailscale](https://tailscale.com/docs/reference/tailscale-cli/serve).

### Проверка доступности

Приложение преобразует путь импорта в:

```http
GET /health-json/health
Accept: application/json
```

Ответ `2xx` означает, что приёмник доступен. `401` или `403` означает, что Tailscale не подтвердил доступ. `5xx` означает, что tailnet доступен, но сервис приёмника временно не работает.

### Приём данных

```http
POST /health-json/v1/import
Content-Type: application/json
Accept: application/json
X-HealthJSON-Request-ID: <UUID>
```

Тело — UTF-8 JSON. Размер одного тела ограничен iPhone-приложением до 8 MiB. Приёмник должен проверить `schemaVersion`, `kind`, `generatedAt`, период и ожидаемые типы до записи в БД.

Возможны два значения `kind`:

| `kind` | Назначение | Как обрабатывать |
| --- | --- | --- |
| `health-agent-context` | Полный снимок последних 365 дней | Атомарно заменить текущий снимок, если `generatedAt` новее. |
| `health-agent-delta` | Короткое обновление за последние 3 дня | Заменить нормализованные строки только внутри поля `period`; не дописывать слепо. |

`rowFormats` описывает порядок значений в компактных строках. Приёмник не должен угадывать порядок колонок. Для повторной доставки одинакового `X-HealthJSON-Request-ID` или уже обработанной ревизии верните `409 Conflict`: iPhone считает `2xx` и `409` успешной доставкой и удалит запись из очереди. Для корректного, но устаревшего снимка также верните идемпотентный успешный результат, не перезаписывая более свежие данные.

Верните `422 Unprocessable Content`, только когда JSON или схема действительно некорректны. Приложение отбросит именно эту запись очереди; для временной ошибки верните `5xx`, чтобы iPhone повторил отправку с экспоненциальной задержкой от 5 секунд до 5 минут.

Не записывайте тело запроса, UUID устройств, медицинские данные или полный URL в обычный лог. Для аудита достаточно времени, `X-HealthJSON-Request-ID`, статуса, версии схемы и результата валидации.

## 2. Чтение из iCloud Drive

Основные файлы находятся внутри папки, которую пользователь выбрал в приложении:

```text
<выбранная папка iCloud Drive>/Health JSON/Agent/health-context.json
<выбранная папка iCloud Drive>/Health JSON/Agent/health-context.csv
```

Если выбрана корневая папка iCloud Drive, на Mac это обычно соответствует `~/Library/Mobile Documents/com~apple~CloudDocs/Health JSON/Agent/…`. Каждый публичный файл заменяется атомарно. JSON — канонический контракт: читатель должен открывать только точный JSON-путь, декодировать файл целиком и обрабатывать его лишь если `generatedAt` отличается от сохранённой последней ревизии. Не подхватывайте iCloud-конфликты, временные файлы или `Agent/Inbox` как полный снимок.

Готовый беззависимостный помощник для такого читателя:

```sh
python3 mac/healthjson.py agent-delta \
  "$HOME/Library/Mobile Documents/com~apple~CloudDocs/Health JSON/Agent/health-context.json" \
  --state "$HOME/.healthjson-agent/state.json" \
  --days 365
```

Он возвращает `initial`, `changed` или `unchanged` и сохраняет локальное состояние. Передавать годовой файл модели при каждом запуске не нужно.

## CSV

`health-context.csv` создаётся рядом с JSON при каждом полном снимке. Его колонки фиксированы, значения экранированы по RFC 4180 и кодировка — UTF-8. Поля `details_json` содержат JSON только для составных объектов (тренировки, кольца активности и специальные записи). CSV пригоден для анализа таблицей, но не является контрактом API.
