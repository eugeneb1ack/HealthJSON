# Tailscale и приватный API Health JSON

Этот режим нужен, когда JSON-снимок должен оказаться на вашем устройстве-приёмнике без ожидания синхронизации iCloud Drive. Это **не Tailscale Admin API** и не публичный webhook: Health JSON отправляет обычный HTTPS-запрос в ваш личный сервис, доступный только внутри tailnet Tailscale.

Получателем может быть **любой** совместимый узел: Mac, Linux-компьютер, NAS, Raspberry Pi, домашний сервер, VM или устройство со своим HTTPS-сервисом. Слово «Mac» в старых примерах — лишь пример, а не требование.

## Схема

```text
iPhone + Health JSON + Tailscale
              │
              │ HTTPS внутри tailnet
              ▼
receiver.example-tailnet.ts.net
              │  Tailscale Serve (TLS и правила tailnet)
              ▼
  локальный сервис на 127.0.0.1:8080
              │
              ├── база / своё приложение
              ├── CSV- или BI-процесс
              └── AI-агент
```

У Tailscale есть два разных режима, и для личных медицинских данных нужен только первый:

| Режим | Назначение | Для Health JSON |
| --- | --- | --- |
| **Tailscale Serve** | Публикует локальный сервис только узлам вашего tailnet; к нему применяются ACL/grants tailnet. | Используйте. |
| **Tailscale Funnel** | Делает сервис доступным из публичного интернета. | Не используйте. |

Официальная документация Tailscale подтверждает это различие и описывает Serve как маршрут к локальному сервису для устройств tailnet; у Funnel другая задача — публичный интернет. [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve), [CLI reference](https://tailscale.com/docs/reference/tailscale-cli/serve).

## Что требуется до настройки

1. На iPhone установлено Health JSON, выдан HealthKit-доступ и хотя бы один полный снимок уже успешно создан.
2. На iPhone установлен Tailscale, пользователь вошёл в нужный tailnet, соединение активно.
3. На устройстве-приёмнике установлен Tailscale, оно входит в тот же tailnet или разрешённый ACL/grant путь.
4. На приёмнике есть локальный HTTP-сервис, принимающий запросы на `127.0.0.1:8080` (порт можно выбрать другой). Он отвечает на health endpoint и принимает импорт согласно [контракту интеграции](INTEGRATION.md).
5. У владельца tailnet включена возможность HTTPS/Serve. При первом запуске `tailscale serve` CLI сам предложит пройти нужное подтверждение, если HTTPS ещё не разрешён.

Не вставляйте в приложение чужой адрес и не рассчитывайте на один постоянный «адрес Mac». Каждый пользователь настраивает собственный адрес приёмника, и адрес можно безопасно поменять позже.

## Настройка приёмника

### 1. Поднимите локальный сервис

Сервис слушает только loopback-интерфейс, например:

```text
127.0.0.1:8080
```

Он должен реализовать:

```http
GET  /health-json/health
POST /health-json/v1/import
```

При таком размещении порт не открыт напрямую в домашней сети или интернете. Входной HTTPS-трафик завершает Tailscale Serve и проксирует к локальному сервису. Подробный протокол и коды ответа — в [INTEGRATION.md](INTEGRATION.md).

### 2. Опубликуйте его только в tailnet

На устройстве-приёмнике выполните:

```sh
tailscale serve --bg --https=443 8080
tailscale serve status
```

`--bg` оставляет конфигурацию работать после возврата в shell. Современный CLI принимает номер локального порта как target; он проксируется к loopback-сервису. В выводе `status` будет адрес вида:

```text
https://receiver.example-tailnet.ts.net
```

Если на системе Tailscale требует прав администратора или показывает URL для разрешения HTTPS, выполните предложенный им шаг и повторите команду. Не заменяйте `serve` на `funnel`.

Проверить конфигурацию в машиночитаемом виде можно так:

```sh
tailscale serve status --json
```

### 3. Проверьте путь из tailnet

С другого устройства, которое уже имеет разрешение ACL, выполните:

```sh
curl --fail --silent --show-error \
  https://receiver.example-tailnet.ts.net/health-json/health
```

Успешный ответ — любой `2xx`. Нормальный JSON-ответ может выглядеть так:

```json
{"status":"ok"}
```

Проверяйте этот URL только из доверенного tailnet; он не должен быть доступен из обычной публичной сети.

### 4. Подключите iPhone

1. Откройте в Health JSON **«Tailscale и API»**.
2. В поле **«Адрес приёмника в Tailscale»** вставьте адрес из `tailscale serve status`:

   ```text
   https://receiver.example-tailnet.ts.net
   ```

   Можно вставить и полный путь, но он не является настройкой: приложение намеренно отбросит его, query и fragment и сохранит только нормализованный URL импорта:

   ```text
   https://receiver.example-tailnet.ts.net/health-json/v1/import
   ```

3. Нажмите **«Сохранить адрес»**.
4. Включите **«Отправлять через Tailscale»**. Приложение проверит `GET /health-json/health`; сначала дождитесь статуса «Подключено».
5. Нажмите ручное **«Обновить данные»**. Это создаст полный JSON+CSV и отправит JSON в очередь API.

Health JSON принимает только HTTPS-адреса с хостом, оканчивающимся на `.ts.net`. Это специально не позволяет случайно отправить медданные на обычный сайт. Нельзя указать IP-адрес, `http://…`, произвольный домен или путь другого API.

## Что и когда отправляется

| Событие | Файл в iCloud | API-пакет при включённом Tailscale |
| --- | --- | --- |
| «Обновить данные», «Обновить из Здоровья», «Поделиться» | Свежий полный JSON и CSV | Полный `health-agent-context` JSON. |
| Изменение HealthKit в фоне | Короткая дельта в `Agent/Inbox` | `health-agent-delta` JSON с окном последних трёх дней. |
| Суточная сверка | Новый полный JSON и CSV | Полный `health-agent-context` JSON. |
| Приёмник недоступен | JSON/CSV не теряются | Пакет остаётся в защищённой очереди iPhone и повторяется. |

Одна полезная граница: iOS не обещает выполнение фонового кода с фиксированной периодичностью. Нажатие ручной кнопки — единственный способ потребовать обновление прямо сейчас.

## Повторы, очереди и смена адреса

Перед отправкой полный пакет пишется в защищённую очередь приложения. Одна передача ограничена 8 MiB. При сетевой ошибке или `5xx` Health JSON повторяет доставку с экспоненциальной задержкой — от 5 секунд до 5 минут. Ответы `2xx` и `409 Conflict` означают успех; `422 Unprocessable Content` отбрасывает именно некорректный пакет.

Очередь разделена по хешу адреса. Если пользователь меняет приёмник с `old.example.ts.net` на `new.example.ts.net`, старые неотправленные медицинские данные не уедут на новый хост. После ротации:

1. отключите тумблер доставки;
2. сохраните новый адрес и проверьте health endpoint;
3. включите доставку;
4. сделайте один ручной полный экспорт.

Удалить адрес из приложения можно кнопкой **«Удалить адрес»**. Чтобы выключить публикацию на самом приёмнике, выполните:

```sh
tailscale serve --https=443 off
tailscale serve status
```

## Требования к приложению-получателю

Приёмник — полноценная граница доверия, даже внутри tailnet. Он должен:

- принять тело UTF-8 JSON не больше 8 MiB;
- проверить `schemaVersion == 1`, `kind`, `generatedAt`, период и наличие ожидаемых структур до записи в БД;
- использовать `kind` + `generatedAt` и при необходимости хеш тела для идемпотентности; `X-HealthJSON-Request-ID` — идентификатор одной HTTP-попытки, а не постоянный идентификатор пакета;
- атомарно заменить полный снимок, только если он новее сохранённого;
- для дельты заменить нормализованные строки только внутри объявленного `period`, а не слепо дописывать;
- не писать тело запроса, сам JSON, персональные показатели или полный URL в обычные логи;
- ограничить Tailscale ACL/grants только нужными пользователями и узлами.

Минимальный протокол, статус-коды, пример health endpoint и безопасный iCloud reader описаны в [INTEGRATION.md](INTEGRATION.md). Для AI-сценария лучше хранить сводку и дельты, а не автоматически отправлять модели весь годовой файл в каждом запросе; см. [AGENT_INSTRUCTIONS.md](AGENT_INSTRUCTIONS.md).

## Диагностика

| Симптом в приложении | Причина / проверка |
| --- | --- |
| «Адрес должен быть HTTPS в tailnet» | Введите свой `https://…ts.net` URL, не IP и не публичный домен. |
| «Нет связи» | iPhone или приёмник не подключён к Tailscale, DNS `.ts.net` не разрешается, сервис offline или endpoint не отвечает за 10 секунд. |
| «Доступ запрещён» | Tailscale ACL/grants не разрешают iPhone обращаться к приёмнику; также возможны `401`/`403` от самого сервиса. |
| «Сервис временно недоступен» | Установлено соединение с tailnet, но получатель вернул `5xx` или другой ошибочный статус. Проверьте локальный процесс и `tailscale serve status`. |
| Есть неотправленные обновления | Приёмник пока недоступен. Не нужно экспортировать заново: включённый Tailscale повторит очередь; новый ручной снимок допустим, если нужен именно полный актуальный пакет. |
